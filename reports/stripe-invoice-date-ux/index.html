Stripe invoice date: review, round 1

Target: synder-ux-prototypes/prototypes/stripe-invoice-date · 2026-10-06 · Lenses: UX ×3, Domain (accountant), Clarity (business owner). Trust, A11Y and Fidelity were not run (default lens set; no Figma reference) · the state map was recorded in real Chromium · validator-check.js verify PASS, 20 findings

Verdict: covers 3 of the FDD's 4 surfaces, and the RevRec confirmation is well written. Two interactions contradict the spec, and both affect the books: confirming a new Schedule start re-dates an existing schedule, and the RevRec lock never lifts. The Sync details drilldown (S1.5) is missing.

Critical and High

WhereProblemFixLenses
RevRec · Schedule details table After Confirm, the existing row sub_after_release_3c1b changes its Schedule start from 28 Dec 2025 → 6 Jan 2026, and then to the text “Payment date”. The modal just said “Existing recognition schedules keep their current dates.” On the FDD's worked example, that moves $10,000 of recognition out of a possibly closed December. Leave existing rows unchanged on Confirm. Show only dates in a date column, never an option name. UX ×3, Domain (Critical), Clarity (Critical)
PT · RevRec lock Following “Change Schedule start date instead →” and setting Payment date doesn't unlock Invoice date: the select is still disabled and the message is still shown, because the lock is a fixed variant. The locked select also always shows Created date, whatever value is actually in effect. Derive the lock from the current Schedule start, and show the value actually in effect. UX ×3, Domain
PT · Sales tab · “Payment posting date” “Payment” is too narrow. This setting dates every cash-side (balance-transaction) entry: sales receipts, refund receipts and expenses. It also clashes with the Summary option “Payment date” (when the customer paid). vocabulary.md also replaces “post” with “sync”. A label that covers all balance transactions, without “posting”. Decide together with the FDD author. Domain
PT · Invoice date help It says what the two dates are, but not what the choice changes: which month the invoice and its revenue land in. To an owner, “created” and “issued” read as the same thing. One plain line on the effect. Use “Date of issue” (the wording on the Stripe PDF) to anchor “issued”. Clarity

Medium (polish)

  • Two save models on one tab. The select auto-saves with a “Saved” toast, and an Update button on the same tab shows “Settings updated”. The same happens on the Sales tab. (UX ×3)
  • Invoice date row is overloaded. It has a New badge, a help sentence, a defaults caption and a blue callout, about 70 words for a two-option select. The caption says existing connections stay on Created, while the select opens on Issued, and nothing says which kind of connection this is. (UX ×3)
  • Prototype notes rendered as product UI: “invented chrome (not live in demo)”, “Sync lock:”, “Issued date column”, “Was ‘Posting date’…”, the “Plan state:” switch inside the Summary card, and “Datasource dating matches Per Transaction rules.” (UX, Clarity)
  • RevRec: “Schedule start date” appears twice (heading + row label), each with its own description. (UX)

Automatic checks

  • 27 text elements under 14px: badges “New”, “Renamed” and “Upgrade to use” (11–12px), the lock message and its link, the defaults caption, “This feature is available on higher plans”, the Sync mode switch and the variant bar (13px).
  • Button radii are within 4px. The fonts are Roboto and Material Icons Outlined (loaded).

Not covered by the prototype

  • Sync details / transaction drilldown (FDD S1.5). Missing. This is the only place a user can see that the books date differs from the created date in the table.
  • Trial and new-connection states. No variant for either.
  • Summary below Pro. The whole select is disabled, so below-Pro users lose Invoice created date and Payment date, which they can pick today. The FDD contradicts itself here (§2 gates only the new values; S2.3 gates the control).
  • Escape doesn't close the RevRec modal. Only × or Cancel do. The A11Y lens wasn't run, so this was recorded during recon only.
  • Invoice date is the first row on the tab, above the existing toggles. The FDD doesn't specify a position.
  • Upgrade plan, Learn more → and How to change mode links go nowhere (href="#").
