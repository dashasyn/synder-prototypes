Which variant: UX and Business owner pick Variant 2. It has one focal point at first setup and opens Stock check on the differences, with bulk actions across stores. The Accountant picks Variant 1, for the precise setup wording and the status tooltips. Recommended: Variant 2 plus two V1 pieces: the status tooltips on the tiles, and the step name “Set Created product to Inventory”.

Risks of each

Variant 1

  • First setup has competing focal points: an info alert, three "Connect store" buttons, and empty Activity/Stock check/Sync blocks are all visible before any store exists.
  • In the 435px stores column, a card that needs setup grows to 918-1082px tall and pushes other stores below the fold.
  • The Stock check tab is a run log: with differences in several stores the user has to open each comparison separately, and there is no cross-store bulk action.
  • The store-missing hint differs between the connect dialog ("Add it first in Settings › Add integration.") and the card footer ("Connect it first in Organization settings").

Variant 2

  • There are two setup models: the first store uses a wizard (inventory, then location, no mapping), later stores use the card's 3 numbered steps (location, inventory, mapping) in a different order.
  • The top-line tiles have no tooltips, so Held/Failed/Pending are undefined numbers.
  • After Finish setup, the next required action (Enable) is signalled only by a toast and sits in the narrow left column under four "–" tiles (KF-2 risk).
  • Gap: the cross-store bulk "Update Shopify qty" dialog was only exercised with one store's differences, so it is unknown whether it groups amounts by store and comparison date when several stores are selected.
  • A failed nightly check appears only as inline text in the "Latest comparison" line, which is easy to miss next to "No unresolved differences."

Findings

HighBothUX ×5 (V1 3/3, V2 2/3)

1. A ready store looks finished while sync is still off

After the last setup step the store card says “Ready” and its only button is “Map products”. Enable sits in another column. In V1 the alert that said “After that, click Enable” disappears as soon as the first store connects. In V2 the only pointer is a toast that goes away after 3 seconds. This is the KF-2 pattern: the user believes they're done, and nothing is ever sent.

Fix: While sync is Disabled and at least one store is ready, show a line that stays on the page: on the ready card (“Ready · turn on sync to start sending”) or in the alert, now pointing at Enable. Zero new controls: it can reuse the existing alert slot.

HighBothUX ×5, Accountant, Business owner

2. “Stock is the same” shown next to a store that was never compared

State 3: “The last check of My good flowers failed … so its stock wasn't compared.” Directly under it: a green tick and “Stock is the same in QuickBooks and Shopify.” On the V2 differences page the failure is only grey text in the “Latest comparison” line, and the table says “No unresolved differences.” The accountant's rule: a match can only be claimed for what was compared.

Fix: Name the store in the all-clear (“My ceramic plates: stock is the same”), or hide the all-clear while any check has failed. On the V2 page, show the failed store as an error line above the table, with Compare now.

HighBothAccountant ×2, Business owner ×2

3. “Created product should be: Inventory” isn't explained, and it changes the books

The step only says which value to pick. It doesn't say what the setting does: from then on, products Synder creates in QuickBooks are Inventory items, so their sales post Cost of Goods Sold and reduce Inventory Asset. Business owners are afraid to touch an unexplained setting. Accountants make a change that affects the general ledger without knowing it. In V2 the step is also titled “Enable inventory tracking”, which is the name of a different QuickBooks setting.

Fix: Keep the exact setting name and add one helper line plus Learn more: “Products Synder creates in QuickBooks from now on become Inventory items, so they track quantity and post Cost of Goods Sold.” In V2, rename step 1 to “Set Created product to Inventory”, the same as on the card.

MediumV2UX ×3

4. Two different setup orders for the same store

Onboarding (first store) uses “1 Enable inventory tracking → 2 Choose location”. The card for every later store uses “1 Choose location → 2 Set Created product to Inventory → 3 1 item needs mapping”. The order and names differ, and there's an extra step.

Fix: Use one order and the same labels in both. Remove the number from the mapping row, because mapping doesn't block Enable (your rule).

MediumV1Accountant (rated Critical), Business owner

5. The Revert dialog doesn't say that QuickBooks stays as it is

“Push -24 back to the store? This writes the opposite adjustment in Shopify.” The new row then reads “Revert of Bill #1042” in the QuickBooks document column, which looks like the Bill itself was reversed. In fact Shopify now differs from QuickBooks by 24, and the next stock check will flag it.

Fix: Add one sentence: “QuickBooks isn't changed. Shopify will differ from QuickBooks by 24 until you fix it in Stock check.” The row should read as a Shopify adjustment, not as a QuickBooks document.

MediumBothUX, Business owner, Accountant

6. The Update Shopify qty dialog shows signs, not results, and points to a button that isn't there

“Ceramic plate 24cm: +8”: a non-expert can't tell whether Shopify ends at 140 or gets 8 more. The dialog says “If the stock changed since then, click Compare now first”, but the comparison page has no Compare now. The accountant also flags a queued change for the same item (Mug set −1, Pending while paused) that could be counted twice. That's a dev question: does Update send a delta or set the quantity?

Fix: Use the same words as the Overview block: “Ceramic plate 24cm: Shopify 132 → 140 (same as QuickBooks)”. Put Compare now on the comparison page (for that store). Ask dev how pending changes and the update interact.

MediumV1 (shared tab)UX ×2

7. Activity with All stores is grouped by store, not sorted by time

State 3, All stores: 16:58, 15:20, 11:05 (plates), then 14:40, 12:15 (flowers). The newest change for the second store sits below older ones. This is a sample-data bug in the prototype.

Fix: Sort newest first across all stores.

Polish

  • V2 tiles have no tooltips. The V1 Activity block explains Held/Failed/Pending/Applied on hover (comparison pass, accountant and business owner).
  • The “Don't see your store here?” help points to two places: the dialog says “Settings › Add integration”, the card footer says “Organization settings”. Use one.
  • The Held reason “Item not matched” uses a different word from the Mappings tab (“Not mapped”, “Map products”). The validators asked again for a fix action on the row. You turned that down on Oct 2 (“can't filter mapping by name”), so only the wording is open.
  • V2 “Previous comparisons” also lists the latest comparison, which the main table already shows.
  • V2: Connect store with nothing chosen is enabled and shows a toast, while Finish setup is disabled with a tooltip. Use one rule.
  • Accountant: which Shopify quantity is compared (On hand, Available, Committed)? This is product logic. Add it to the dev questions.

Rejected after checking

  • V2 UX-4 (resolved rows vanish with Unresolved only off): the recon turned Unresolved only back on before the bulk update, so the validator misread the order of steps. Not a defect.

Not reviewed
