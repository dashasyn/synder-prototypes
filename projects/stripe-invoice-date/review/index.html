Stripe invoice date (my prototype): review, round 1

Target: projects/stripe-invoice-date · 2026-10-07 · Lenses: UX ×3, Domain (accountant), Clarity (business owner). Trust, A11Y and Fidelity were not run (default lens set; no Figma) · the state map was recorded in real Chromium, 12 zones · validator-check.js statemap PASS, verify PASS · 14 findings · automatic checks clean (no text under 14px, no radius over 4px, no horizontal overflow)

Verdict: the flows work and match the FDD, and nothing from round 1 of the other prototype came back. One real design hole: the RevRec lock's way out. Three lenses found that following the lock note can leave the books and the schedules on different dates. The rest is copy, plus one missing row in Sync details.

Critical and High

WhereProblemProposed fixLenses
Invoices lock ↔ RevRec Schedule start The note says “To change it, change Schedule start date.” If the user follows it and picks Invoice issued date, Invoice date stays locked on Created date. Schedules now start on issued while the books use created, and the only way to unlock it (Payment date) is never mentioned. The FDD doesn't say which value the Sync setting is locked at. This is the gap raised on 2 Oct. Product decision: while locked, Invoice date follows Schedule start (issued → Issued, created → Created). At minimum, the note names Payment date as the way out. UX ×3 (corroborated)
Invoices lock note wording “Locked while Revenue Recognition starts schedules from the invoice date.” “The invoice date” is both the old RevRec label (now renamed) and the name of the locked setting itself, so it reads as “Invoice date is locked by the invoice date”. Name the option and the product: “Locked while Synder RevRec starts schedules from the invoice created date. To change it, change Schedule start date.” Domain, Clarity
Summary · Sales recording date Invoice issued date sits on an org-level setting, but only Stripe invoices have one. Nothing says what Shopify sales or non-invoice charges get. (This was already an open question for the FDD author.) FDD author: make it per integration, or state the fallback in the description. Domain
Summary · AR sentence “With Payment date there is no Accounts Receivable in summaries.” Domain called it unsourced. In fact it's the live string, kept from production. Clarity: a business owner doesn't know what AR is. Keep the live sentence and add a plain-word gloss: “Accounts Receivable (money customers still owe you)”. Confirm with the FDD author that it still holds when Sync open invoices is on. Domain, Clarity

Medium

  • Sync details, example B. When the invoice was booked on the created date, the Date in books row disappears, which leaves two dates and no answer to which one went to the books. Show the row in both cases (“Dec 28, 2025 · created date, per Invoice date setting”). (UX ×2, Clarity noted)
  • RevRec confirmation dialog. It says nothing about the effect on the Stripe Invoice date (locked for created/issued, editable for payment). Add one clause per chosen value. (UX ×2)
  • Summary scope. The description doesn't say whether past summaries change. Careful: the FDD expects past periods to be able to follow the new value (dual snapshot, S2.4, still open with engineering), so “from now on” could be wrong here. Decide after engineering confirms. (UX)
  • “Payment posting date”. “Posting” is accountant wording, and the vocabulary uses “sync”. Clarity suggests “Payment date in books”, to match Sync details. This is the same naming question as before. (Clarity)

Gaps the validators named

  • No org state has Invoice date = Issued and RevRec turned on afterwards (the reverse mismatch: books on Issued, schedules on Created).
  • Below Pro and RevRec together is not a selectable state.
  • There's no success message after Update, after a Summary change or after RevRec Change. Whether production shows a toast there isn't captured, so this wasn't reported as a defect.
  • Learn more / Upgrade plan links go nowhere in the prototype.

Not re-flagged (decided)

Placement under Sync unpaid (open) invoices · the plan-gate pattern · the option-level Summary gate · Update as the save model. Listed in review/findings-log.json → declined.
