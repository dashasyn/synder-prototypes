C · Hover chevron (default)

Medium · ux2 · UX-1 · Collapsed rail: group flyout (for example Transactions) when the pointer moves diagonally to a lower sub-page
A flyout opens on mouseover with no hover intent and no safe zone, so a diagonal move toward a lower row crosses the next rail icon, which swaps in that icon's tooltip and then hides it.
Impact: A user moving from the Transactions icon to Period lock or Troubleshooting loses the menu partway and must go back and trace an L-shaped path, and this repeats on every deep group in the rail.
Fix: Keep the open group flyout while the pointer moves toward it, using a short hover-intent delay before switching or a safe triangle, as in Stripe's collapsed nav.
Evidence: action: Option C, Admin view, 1280x800, collapsed to the rail. Hovered the Transactions icon at (25,203); the flyout opened at x50 y181, 200x215. Moved the pointer in 25 steps to Period lock at (117,341).; observed: The flyout's data-for changed from 'tx' to 'inventory' (text 'Inventory sync Beta') and the flyout ended hidden. The same target reached by an L-shaped path (right first, then down) kept the flyout open. A shallower diagonal from Smart rules to Recipes also held, so the bug depends on how far down the target row is.
Medium · ux3 · UX-1 · Org selector · Admin view: current-org row
Now that Recently selected is gone, the admin's current org is just one row in an alphabetical list of about 40 orgs. The panel opens at the top and never scrolls to that row, and the row has only a check icon. It lacks the selected-row background that the current row gets in the Per transaction, Summary and Accountant views.
Impact: An admin opening the selector cannot see which org is current: PT_3 is row 25 and Tea Leaf Collective is row 36, both below the roughly 13 rows visible in the 560px panel. When they do scroll there, the current row is styled differently from the other three views, and with the production org count it is effectively lost.
Fix: Give the Admin current row the same .cur selected background as the other views, and either show the current org pinned above the list or scroll it into view when the panel opens.
Evidence: action: Admin view: picked Tea Leaf Collective via Enter search, reopened the selector with an empty field; read renderSwitch() admin branch; observed: Statemap 'current-org row: null'. Tea Leaf Collective + check is the 36th of about 40 rows. The admin opt() template has no ' cur' class (it does in the non-admin branch, line 714), and there is no scrollIntoView on open. scrollIntoView runs only in setHl on arrow keys.
Medium · domain · DOM-1 · Org selector · Admin view, flat organization list
The accountant view now separates the firm from its clients under "Firm" and "Clients", but the admin list shows the same firm ("Northwind Bookkeeping") as a plain row among its own clients and unrelated organizations, with no firm or client marker.
Impact: A support admin switching into a firm's account cannot tell the firm workspace from a client organization, or which clients belong to which firm, so they can open and change the wrong client's sync settings and books.
Fix: In the admin list, mark firm rows as Firm and show each client organization's firm, matching the Firm and Clients split in the accountant view.
Evidence: quote: NB Northwind Bookkeeping NO Northwind SaaS Ltd; source: vocabulary.md Organizational Terms: "Accounting firm" and "Organization" are defined as distinct units; the domain lens also covers multi-client workflow gaps.
Medium · domain · DOM-2 · Success toast after picking a client (Accountant view)
The new client toast uses a "Label: value" format with no exclamation mark, which does not follow Synder's success-toast pattern.
Impact: The confirmation that the user is now working in another client's books reads as a status label, not a completed change, and differs from the rest of Synder's success toasts.
Fix: Follow the {Thing} {past participle}! pattern, for example "Switched to Granite Peak Dental!", and apply the same pattern to the firm and organization variants.
Evidence: quote: Client selected: Granite Peak Dental; source: vocabulary.md Toast Patterns: Success (enable/change/update): `{Thing} {past participle}!` — e.g. "Settings updated!"; Rules: "Enable/change/update → exclamation mark"

B · Edge button

Medium · ux · UX-1 · Edge toggle vs the bottom rail tiles (What's New, Settings)
The toggle is absolutely positioned and the nav does not reserve space for it, so in the rail it covers the right third of the Settings tile and the bottom of the What's New tile.
Impact: A user who clicks the right side of Settings in the rail expands the sidebar instead of opening Settings, so they have to collapse it again and click again. The same overlap exists, smaller, on the right end of Settings and What's New in the expanded sidebar.
Fix: Give the nav scroll bottom padding equal to the toggle's height plus its 20px offset so the last row ends above the toggle, or raise the toggle above the bottom links.
Evidence: action: Collapsed to the 50px rail with the Edge toggle, then compared the measured toggle box with the bottom rows. The rows are pinned by .sb-sec.bottom margin-top:auto; .sb-scroll padding-bottom is 8px; rows are 32px with 1px gaps; rail rows span x6–44.; observed: Toggle box x31–65 y748–780. Settings tile works out to x6–44 y760–792, giving a 13×20px overlap; What's New works out to y727–759, giving 11px of vertical overlap. Expanded: toggle x213–245 vs Settings row x8–222, a 9px overlap. The toggle has z-index 25, so it takes the click.
Medium · ux · KIT-1 · Edge collapse toggle in the collapsed rail
In the rail, the shared rule body.rail .sb-in > .sb-collapse {width:34px} overrides the edge button's 32px width, so the round button turns into a 34×32 oval.
Fix: Scope the 34px rail width rule to non-edge modes (e.g. body.rail:not(.m-edge)) so the edge button stays a 32×32 icon button with radius-full.
Evidence: measured: Expanded toggle box 32×32; collapsed toggle box 34×32 (statemap, Collapsed sidebar zone), border-radius var(--radius-full); kit: Buttons 32px; only circles are round (32×32)

A · Icon rail

Medium · ux · UX-1 · Rail org avatar (top of the 50px rail, shows 'PT')
In the rail, the org avatar is the only icon that shows nothing on hover. Every nav icon gets a tooltip or flyout, but the org shows only 2-letter initials. Those initials collide in the demo list (RE ×4, SU ×2, TE ×3, NO ×2, SH ×2).
Impact: With the menu collapsed, users can't confirm which org they are in without opening the full selector. Users who move between same-initial orgs (the RevRec copies) will act in the wrong org or keep reopening the panel.
Fix: Give the rail org avatar the same hover tooltip pattern as the nav icons, showing the full org name (e.g. 'PT_3 (copy) (2140)').
Evidence: action: Playwright 1280x800, sb-mode=rail, collapsed. Read the .sb-org attributes, hovered .sb-org, then hovered a group icon for comparison.; observed: .sb-org title='' and data-fly=null, text 'PT'. After hovering it, #fly hidden=true with empty text. Hovering a .sb-group[data-fly] opens #fly with the header and 5 rows. Data-fly is on all 13 nav icons and on admin, but not on the org avatar. This is new rail-specific evidence for open item R1-hover-CLR-1.
Medium · ux · KIT-1 · Rail flyout / tooltip menu (#fly) and its rows (.fly-h, .fly-i)
The round-1 kit block sets the flyout to radius 4 and shadow-menu. It sits at index.html line 253/260, but the older #fly rules at lines 285–292 come later with the same specificity and win. So the rail flyout still renders round-1 drift. kit-conformance missed it because #fly is hidden when that check runs.
Fix: Delete the older #fly radius, padding and shadow declarations at lines 285–290, or move the kit block after them. Use var(--radius-sm), var(--shadow-menu) and 4/8px padding.
Evidence: measured: Live, rail, hovering a group icon: #fly border-radius 8px, padding 6px, box-shadow rgba(16,24,40,0.14) 0 8px 24px. .fly-i and .fly-h border-radius 6px.; kit: radius 4px (--radius-sm); menu shadow --shadow-menu (0 5px 5px -3px rgba(0,0,0,.2), …); spacing on the 4px grid
