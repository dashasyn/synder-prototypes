Product questions raised by the reviews and by new constraints. The Daily Summary row is already shown in the prototype and need engineering to confirm them. The others are kept out of it, so it shows only what the product can do today.

FeatureProblem it solvesProposalQuestion for engineering
Organizations per connection
Blocker for accounting firms		 Live (v11.7.107): a token or signed-in app works in every organization the user belongs to; the Synder Allow page says so. A Full token meant for one client can resync, roll back or change settings in all of them. Limit a connection to the organization it was created in, or let the user tick organizations. The prototype now uses the live wording ("in the organizations you belong to") until this exists. Can a token or OAuth grant be limited to selected organizations?
Daily Summary organizations
Shown in the prototype		 An assistant can't be connected to an organization with Daily Summary. Summary view: Request only, with the live sentence "Connecting your own AI assistant is not available for organizations with Daily Summary yet." No table. Can a connection made in another organization reach a Daily Summary one? Assumed no.
Activity log After the assistant changes something, nobody can tell a client or auditor what it did. Per connection: action, organization, object, time. Opened from the table row. Are API calls logged per token today? Last used suggests some tracking exists.
Expiry Tokens "don't expire on their own", so forgotten Full tokens stay live. Optional expiry at Generate, default 90 days, plus an Expires column. Does the token model support an expiry date? (The View tokens permission already mentions "expiry".)
Test connection After setup, nothing confirms it works; "Active · Never used" reads as connected. Last step of each route waits for the first request and says "Connected". Can the page learn about the first call for a token or signed-in app?
