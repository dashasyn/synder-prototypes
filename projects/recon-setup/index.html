Reconciliation setup — 3 variants

Replacing “Reconciliation details”

The current setup page asks for six required decisions and prefills none of them: date range, integration, clearing account and two separate “Automation mode” selectors. All three variants below start from a prefilled state and differ in how much form survives.

Variant A

One line

The setup is a sentence, not a form. Fields exist but stay closed until asked for.

  • Zero decisions to run
  • “Change details” reveals all four fields
  • Summary restates itself when a field changes
  • Smallest surface, least discoverable
Open A
Variant B

One column

Keeps real fields, drops the Synder / Integration mirror. Everything prefilled, one flow.

  • Three groups: what to check · period · data
  • One data question, not two automation modes
  • Shopify + Xero switches to a named required file
  • Run sits under the form, not top-right
Open B
Variant C

No form

The setup page disappears. One row per clearing account, each with its own Run.

  • No default to guess — the user picks by acting
  • Shows coverage truth: one run per integration
  • Period is the only shared control
  • Custom ranges still need a form somewhere
Open C

Fixed in all three

  • Title is New reconciliation, not “Reconciliation details” — details is for viewing something that exists.
  • One verb: Run reconciliation, replacing “Start matching” / “Run audit” / “Start reconciling”.
  • Months offered as presets instead of two free-text date inputs.
  • The read-only promise sits next to the button at normal weight, not as small grey text.
  • No “Get started” explainer above the form, and no site footer bleeding into the overlay.
  • Account list scoped to clearing accounts, so the integration is never ambiguous.
