What v2 changes

v1 covered toggle helpers only and got two things wrong. A parallel audit of the same page — same org, same integration — was run independently; where the two disagreed, I went back to the live page rather than argue. Both audits produced near-identical sentences for about 15 of the 21 toggles, which is the strongest signal in the whole exercise: two passes, one answer.

  • Apply Taxes was diagnosed wrong. I called it duplicate copy. It is worse: the description changes meaning when the switch flips. Corrected, and escalated to a product question.
  • Cancel sync described another toggle’s behaviour. Now states only the outcome it owns.
  • Voice unified. Three rows I had left passive are now Synder [verb]. My reason for leaving them protected a talking point, not a principle.
  • Scope tripled — pickers, nested fields, error strings, plan gates and dead UI were all “phase 2” in v1.
  • Process payouts is rewritten, reversing an earlier decision. Flagged for sign-off.
Three claims I pushed back on and was wrong about. Worth recording, because the pattern matters more than the items: all three came from measuring one tab and generalising, or from checking the wrong artifact.
· “Lending Liability doesn’t exist on my org” — it does, Fees tab, DEFAULT_.loanPayableAccount.USD. I checked it against my toggle list, not my pickers.
· “Empty help icons aren’t widespread” — I counted 7 on the default tab. Across all 11 tabs it is 56, 42 of them visible, none with a tooltip.
· “Two different orgs, needs reconciling” — same org, same integration. There was nothing to reconcile.

The house rules

  1. Toggle helpers state the ON behaviour in present tense. No If you enable / If enabled / If disabled / When "ON" / Enable this setting to / It is an option to / By enabling this configuration.
  2. Synder is the actor when Synder acts. Passive only when QuickBooks or the books is the actor.
  3. One sentence. A second only when OFF is not the obvious inverse, or a dependency has to be stated.
  4. Never “this setting / this option / this configuration.”
  5. Pickers open with Select. Never “Please,”.
  6. Say Synder — never “app” or “the application”.
  7. Links are a plain label plus →. Kill page>>, Learn more >>, Smart rules >>.
  8. “(recommended)” is a chip on the label — grey .chip-neutral, never the coloured .badge-new. An option recommended inside a dropdown stays inline on the option.
  9. A help icon either adds something or goes. Never empty, never the helper verbatim. Keep it only for plan nuance, irreversible risk, or an example that would bloat the line.
  10. Nested fields describe the field, never the parent toggle the user just flipped.

The 10 shapes in use today

“If you enable this setting (recommended)…” · “If enabled (recommended)…” · “If enabled…” · “If disabled…” · “It is an option to assign…” · “By enabling this configuration…” · “When "ON", Synder will be taking…” · “Enable this option to…” · “Enable this setting to…” · “If 'No' app won't receive…”
…plus three rows that already use no conditional at all — the shape everything else is moving to.

Ship order

  1. Remove the empty question icons and name the gear buttons — or give both a real job. Nothing else on this list is visible to a screen reader until this is done.
  2. Label the 7 unlabelled selects. Seven picker rewrites are blocked on this.
  3. Ship the toggle helpers. General and Invoices first — highest confusion, and Invoices contains the two rows the whole argument rests on.
  4. Fix the error strings: Doc Numbers prerequisite, plan gate.
  5. Nested field helpers (5 rows) — cheap, and removes the most embarrassing string on the page.
  6. Pickers pass, including the “app” → Synder language on Fees, Payouts and Application Fees.
  7. Resolve Apply Taxes single-truth and the Auto-sync missing state. Both need product, not copy.

How this was captured

Every toggle flipped individually and flipped back, plus seven ordered scenarios (Auto-sync without Auto-import, location → selector, generic customer → name picker, archive → days field, inventory → accounts, generic tax code → two pickers, cancel-sync after apply-to-txn). These settings save immediately on toggle (POST /v2/settings/…) — six writes occurred, all reverted, and a reload audit confirmed all 21 toggles returned to their starting values. The icon and label audit walks all 11 tabs; measuring only the default tab is what produced the wrong numbers in v1.
