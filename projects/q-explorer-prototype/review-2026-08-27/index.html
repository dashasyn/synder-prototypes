Q-Explorer — prototype review

QMS RPV CH · projects/q-explorer-prototype/index.html · Round 1 · 27 August 2026

Verdict

The structure is understandable; a lot of the controls are not connected to anything. Someone sat in front of this tool can work out what it is for — the landing list, the three-step wizard and the report layout all read correctly, and the auto-generated evaluation name is a genuinely good piece of design. The problems are not comprehension problems. They are three ways to lose or fail to reach your work (C1, C2, C3), and roughly 50 inputs, selects and buttons that look interactive and have no handler at all — including the breakdown control on both DPM reports and every column filter on the raw-data tables.

Read another way: the parts that show you numbers are in good shape, and the parts that let you change what you are looking at are mostly not wired up yet.

Method, and what did not run

Followed personas/VALIDATOR_PROTOCOL.md v2. Recon was a real Chromium pass (Playwright) over all 13 views and three user flows — create an evaluation, manage saved and scheduled reports, read a finished report — in German and English. Both state maps passed validator-check.js statemap, so every panel-opening control has a recorded commit path (open → pick → reach Apply → repeat) rather than just “it opens”.

Critical — corroborated by 4+ independent lenses

C1

Clicking the middle of a filled filter wipes it

Critical
Wizard step 2 — all six filter controls (Kantone, TU's, RPV, Verkehrsmittel, Linien, Haltestellen) · UX ×3 + Trust (4 independent lenses)

.custom-select-trigger lays out three children — label, clear-✕, caret — with justify-content: space-between. That puts the ✕ at the horizontal centre of the control. Measured: the trigger is 542px wide, the ✕ occupies x=769–789, and the centre is x=789. document.elementFromPoint(centre) returns canton-clear.

ReproducedPicked Kanton AG (state ['AG'], label "AG"). Closed the panel. Clicked the trigger to reopen it → panel did not open, state became [], label reverted to "All cantons". Same on TU's: ['BLS'] → []. No message, no undo.

Why it matters. An analyst reopening a filter to check or extend it destroys the scope instead, then runs the evaluation across every canton believing it is still restricted.

Fix. Put the ✕ and the caret in one right-aligned group (or give the label flex:1) so the centre of the control always opens the panel. Shrink the ✕ hit area to its glyph and add a “Cleared — undo” toast.

C2

Editing a saved schedule shows a blank configuration under its name

Critical
Geplante Berichte → Edit · UX ×3 + Trust

The wizard opens titled “Fahrtausfälle DPM – Wöchentlich” with a “Scheduled” badge, but none of the saved configuration is loaded, and the schedule section is hidden (display:none) so the frequency cannot be seen or changed.

ReproducedClicked Edit on the weekly Fahrtausfälle schedule. Read state: selectedPeriod: 'cur_month', selectedTU: [], selectedCantons: [], selectedLines: [] — the defaults, not the schedule.

Why it matters. The screen asserts it is one specific schedule while showing something else. A user changing one canton can replace a scoped BAV report with an unscoped default, or simply misread what is being measured.

Fix. Hydrate the wizard from the stored schedule and keep the schedule section visible in edit mode. If hydration isn’t built yet, title the screen “New evaluation from schedule” instead of the schedule’s name.

C3

Ten finished evaluations cannot be opened at all

Critical
Evaluations list — every Rohdaten Export, Linienanalyse DPM and Datenqualitätsindex row · UX ×3 + Clarity

Only 9 of 28 rows carry an “Anzeigen” button. 10 of the 19 rows with status Fertig have no open action, and the row name is not clickable either (onclick absent, cursor:auto). The only remaining row action is Delete.

ReproducedCounted in the live DOM: 28 visible rows, 9 with an open action, 19 with status done, of which 10 have none. Named examples: “Rohdaten Export – Gestern”, “Linienanalyse DPM – Letztes Jahr, Kanton BE”.

Why it matters. The list says the work is finished and offers no way to see it. That is the create-and-read task failing outright for three of the six report types.

Fix. Give every Fertig row an open path (clickable name + Anzeigen). Where a type genuinely has no viewable output, say so — e.g. “Datei bereit” with a download action.

The dead controls, and the rest of the High findings

H1

Both report breakdown controls do nothing

Critical (report flow)
Anschlusspünktlichkeit “Aufschlüsseln nach” · Pünktlichkeit “Aufschlüsseln” · Recon + deterministic pass

The three-level breakdown is the main analysis control of the DPM reports. On V5 the three selects (#rpt-aufschluss-1/-2/-3) have no onchange attribute at all. On V11 the selects do have a handler, but it only drives the option-disabling cascade — never the table.

ReproducedV5: switched level 1 to “TU (connector)”, then “Line (connector)” — table stayed at 30 rows with an identical Total row and identical columns. V11: switched level 1 Linienbündel → Haltestelle → TU konzessioniert — table stayed byte-identical (20 rows, first column header still “Name / Linienbündel”, same first row). Setting all three levels changed nothing.

Why it matters. Reading a DPM report means slicing it. The control that does that looks fully functional and is inert on both reports.

Fix. Wire the selects to re-render the table (and to relabel the first column to the chosen dimension).

H2

Every raw-data column filter is decorative

Critical (report flow)
Pünktlichkeitsdaten (16 inputs + 3 selects) · Rohdaten Anschluss (11 inputs) · Deterministic pass + recon

27 column search inputs and 3 column selects carry no oninput, onchange or onkeyup attribute. They render as a full filter row under the table headers.

ReproducedTyped a no-match value (“ZZZZ”) and a real value (“10.06.2026” + Enter) into the first column filter of Pünktlichkeitsdaten: row count stayed 10, info line stayed “of 4950 entries”, no empty state.

Why it matters. 4 950 rows across 18 columns with a filter row that filters nothing. The one control a user needs on a table that size is fake.

Fix. Wire them to the existing render function, or remove the filter row until it works. Pagination, by contrast, works correctly.

H3

The first click on a bundle row does nothing

High
Pünktlichkeit report — bundle expander caret · Recon

The caret button ships without the collapsed class while its line rows ship hidden, so the first click re-hides already-hidden rows and only flips the flag. The caret icon is also always expand_more, expanded or not.

ReproducedReproduced 4× from a fresh load: 20 rows → click → 20 rows (nothing) → click → 26 rows → click → 20 rows.

Why it matters. This is the same second-toggle failure class already logged in MISSES.md. A user clicks, nothing happens, and most people conclude the row has no detail.

Fix. Add collapsed to the button’s initial markup (or invert the initial test) and swap the caret icon on toggle.

H4

Run Now with a schedule ticked confirms only half the action

High
Wizard step 3 · UX ×3 + Trust + Clarity (5 lenses)

Ticking “Als geplanten Bericht einrichten”, choosing Monthly and pressing Run Now produces the toast “Evaluation started — running now”. Nothing mentions the schedule, and no new entry appears in Geplante Berichte.

ReproducedTicked the schedule box, set frequency Monthly, clicked Run Now, then opened Geplante Berichte — only the six pre-existing demo schedules were there.

Why it matters. A TU quality lead sets up a monthly DPM report, sees a success message and stops thinking about it. The report never runs.

Fix. State both outcomes (“Auswertung gestartet · Monatlicher Zeitplan gespeichert”) with a link to the new row, and add it to the list immediately. If only one can be committed, disable the combination instead of confirming ambiguously.

H5

Kantone is the only filter that closes when you pick something

High
Wizard step 2 · UX ×3

Of six visually identical multi-select panels, five stay open after a pick and Kantone closes.

ReproducedTested all six in one pass: RPV, Verkehrsmittel, TU's, Linien, Haltestellen → “stays open”; Kantone → “CLOSES on pick”. Adding a second canton by mouse then failed in two attempts, because reopening lands on the centre-mounted ✕ (C1).

Why it matters. The two defects compound: the user learns multi-select from five controls, the sixth breaks the rhythm, and the recovery click destroys the first pick.

Fix. Keep the Kantone panel open after a pick, closing only on outside click, Esc or an explicit Done.

H6

A paused schedule still advertises its next run

High
Geplante Berichte table · Trust

Status reads “Paused” while Next Run still shows a concrete date on the same row.

ReproducedPaused the weekly Fahrtausfälle schedule: Status Active → Paused, action title Pause → Resume, Next Run unchanged at 01.06.2026.

Why it matters. Someone checking whether the June reporting period is covered reads a firm date, assumes it is handled, and does not run it manually.

Fix. Show “— Paused” in Next Run while paused and recalculate on resume.

H7

Four toolbar buttons are wired to nothing

High
Fahrtausfälle report · Pünktlichkeit chart popup · Ausfallmaske · Deterministic pass

No onclick attribute: CSV Export on the Fahrtausfälle report, the treemap camera button, and Snapshot + fullscreen in the chart popup. Separately, the Ausfallmaske’s “Anwenden” and “Zurücksetzen” buttons are also unwired — that filter form has no working commit or reset.

ReproducedClicked V8 CSV Export with the snackbar cleared first: no snackbar, no toast, nothing. The identical-looking button on V5 and V11 shows “Preparing CSV export…”. Chart Snapshot: same, no feedback.

Why it matters. Two buttons that look the same behave differently on adjacent reports, and the Ausfallmaske filter cannot be applied at all.

Fix. Wire the six buttons to the existing handlers, or remove them until they exist.

H8

Escape doesn’t close the chart popup, and focus never enters it

High
Pünktlichkeit chart popup · Recon (A11Y lens did not run)

Escape does not close the overlay — only × or a click outside. Focus is not moved into the modal and not trapped.

ReproducedOpened the popup, pressed Escape → overlay display:flex unchanged. Two Tab presses landed on a background button outside the overlay (closest('#punct-chart-overlay') null).

Why it matters. Keyboard users cannot dismiss the popup and tab straight out of it into the page behind. The Info modals added this week do handle Escape — so the app is inconsistent with itself.

Fix. Close on Escape, move focus to the modal on open, trap it while open and restore it on close.

Medium — worth fixing, not urgent

  1. 37 translation keys exist in neither dictionary. data-i18n keys used in the markup that are missing from both the en and de dictionaries, so those elements never translate and keep their hardcoded German. They cluster in the Ausfallmaske (fa_mask_*, fa_col_*, fa_opt_*) and the raw punctuality columns (punct_raw_col_*, punct_col_ist, punct_col_delta). Visible effect: in EN mode the three breakdown selects still read “Linienbündel”, “Haltestelle”, “Monat”, “TU konzessioniert”, “TU fahrend” — 12 options, identical count in both languages.
  2. “Transport companies” in English inside the German UI. The expandable chip dropdown header on all three report views. Flagged in the June review as UX-1 and still open.
  3. No report tells you when it was generated. The subtitle is empty on all three report views. For a scheduled report that may be days old, there is no way to tell how fresh the figures are. June review UX-4, still open.
  4. Pünktlichkeit has no KPI cards. Anschlusspünktlichkeit has 4 (with a 90% threshold and warning icons), Fahrtausfälle has 3, Pünktlichkeit has 0 and opens straight into the breakdown selects. June review UX-5, still open.
  5. “Schließen” exists on two views out of six. Present on Pünktlichkeit and the raw punctuality view; absent on Anschlusspünktlichkeit, Fahrtausfälle and the Ausfallmaske. June review UX-3, still open.
  6. Four acronyms carry the meaning and none is expanded. DPM, RPV, TU, DQI appear on the type cards and filter labels with no expansion or tooltip anywhere (Clarity, CLR-3).
  7. Deleting uses the browser’s native confirm(). confirm('Delete this evaluation? This action cannot be undone.') — an unstyled OS dialog in a designed tool, and the toast afterwards offers no undo despite the warning. The scheduled list uses a second, separate implementation of the same pattern.
  8. Two design languages in one file. 109 distinct hex values, 41 used exactly once, with two grey ramps mixed — #9CA3AF/#E5E7EB/#374151 alongside #9E9E9E/#E0E0E0/#424242 — plus 13 font sizes and 10 border radii. .rpt-params-bar and .fa-params-bar are byte-identical duplicates (June UX-7).
  9. Secondary text fails contrast. Declared text colours below 4.5:1 on white: #D1D5DB 1.47, #BDBDBD 1.88, #9CA3AF 2.54 (used 40×), #9E9E9E 2.68, #D97706 3.19.
  10. Type cards can’t be reached by keyboard. The six report-type cards are <div onclick> with no role and no tabindex. Tab skips the entire entry point of the tool.
  11. A reversed date range is accepted silently. Entered from 20.08.2026 to 01.08.2026: no validation, no error, Next stays enabled, and the generated name reads “Trip Failures DPM – 20.08.2026 – 01.08.2026”.
  12. Login accepts empty credentials. Clicking Anmelden with both fields blank logs straight in — no validation and no required-field marker. Acceptable as a prototype shortcut, but the screen shows no validation design at all.
  13. Step-3 summary concatenates the filters. “RPV: Tarifverbund ATransport Mode: Bahn NormalspurCantons: AGLines: Bus 10Stops: Aarau” — no separators between the filter values on the confirmation card.
  14. The sidebar shows no location inside a report. No .nav-item is active while a report is open, so the navigation gives no sense of where you are.

M2–M5 and M8 were all raised in the 29 June review and have been open since. Nothing from that round was ever applied.

What works, and should not be touched

  • The numbers hold up. On the Pünktlichkeit report, Delta = Soll − Ist exactly and Wert % = pünktlich / Ist, on the Total row (2 101 488 / 2 048 996 / 1 861 401 / 52 492 / 90,84%) and on all five bundle rows spot-checked. Nothing in the data contradicts itself.
  • The wizard’s auto-naming is genuinely good. Every choice feeds the evaluation name live — “Trip Failures DPM – Current Month, all lines” becomes “…, Mon–Fri” the moment you untick Sat and Sun. It’s the clearest feedback mechanism in the tool.
  • Landing on the evaluations list, not an empty form, is the right call. Grouped by report type, with search, status and period filters that all apply instantly and a real empty state for no-match searches.
  • Pagination on 4 950 rows works properly — First/Previous/1/2/…/495/Next/Last, with the “1 to 10 of 4950” line updating correctly.
  • The custom-period rule shipped this week holds. Selecting a custom range disables scheduling with a reason, clears an already-ticked box, and blocks the edit path — verified in both languages.
  • Chart zoom and reset work (svg width 1044 → 1566 → back), and the Ausfallmaske request does what it promises: the icon becomes a check and a data-sheet link appears.
  • KPI cards with thresholds are the strongest piece of design in the tool — “All day 89,53% ⚠ · Threshold: 90%” tells an analyst the answer before they read a single table row. Which is exactly why Pünktlichkeit not having them stands out.

Suggested order

  1. C1 — the filter ✕. One CSS change, and it is currently destroying user input.
  2. H3 — first click on a bundle row. One class in the markup.
  3. H7 — the six unwired buttons. Copy the handlers that already exist on the sibling views.
  4. C3 — open finished evaluations. Needs a decision: do Rohdaten/Linienanalyse/DQI get report views, or a download action?
  5. H1 + H2 — breakdown selects and column filters. The largest piece of real work, and what makes the reports usable rather than illustrative.
  6. C2 — hydrate the edit-schedule wizard, or rename that screen until it does.
  7. H4, H6 — tell the truth about schedules (confirm both outcomes; no next-run date while paused).

Known gaps in this review

Recorded by the validators themselves so that “not checked” never reads as “passed”:

  1. No loading or in-progress state is recorded anywhere between Run Now and the list reappearing, so progress feedback for a long evaluation is unassessed.
  2. No error state was ever produced in the whole flow — login accepts empty fields, the reversed date range raises nothing — so error copy and recovery are entirely unexamined.
  3. The notify-by-email toggle and address field were never exercised; a control that promises a notification is exactly where an unkept promise hides.
  4. Whether completing the edit-schedule wizard overwrites the original, duplicates it, or does nothing was not tested — C2’s data-loss consequence is inferred from the blank form, not observed.
  5. Whether filter cascading is intended at all is unknown, so it is unclear whether the Linien picker can offer lines outside the selected cantons.
  6. The Failed status appears in the filter but no failed row was inspected, so what a failed evaluation tells the user is unknown.
  7. The first-run empty states of the evaluations list and Geplante Berichte were never reached.
