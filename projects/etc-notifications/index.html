2Unread / All, not New / Passed. "Passed" is ambiguous — it can mean "already seen" or "the event is over". Those are two different axes, and the Events entity already owns the second one with Active / Draft / Finished.
3The row is the message. The sentence from the old Text column, clamped to two lines, so no row can ever force horizontal scrolling. Type as a chip, delay as a red chip, time right-aligned.
4Urgency on the left edge — red critical, amber warning, blue info — plus an icon. Scannable down the whole list without reading a word.
5Per-user delete. Hover a row for the ✕. Every delete gets a 5-second Undo, because in an ops team a mis-click shouldn't lose an alert. Nothing is deleted for anyone else.
6Newest first, grouped under sticky Today / Yesterday / date headers. Today's build sorts by time-of-day and ignores the date — switch to Before and turn notes on to see it.
7Only fields that have a value. This is what removes the horizontal scroll: a platform change shows 8 fields, an announcement shows 1, a mapping-issue alarm shows 2. The old table forced all 14 on every row — 39 of the 63 event-describing cells were "-".
8Same sheet, not a new page. Back returns to the list with scroll position intact. Opening the detail marks it read; "Mark as unread" puts it back if you were only triaging.

Notifications
From a 14-column table to a notification list.

The problem today

  • 14 columns. Of the 9 that describe the event, 39 of 63 cells are "-" — every type must declare all fields, each uses 3–4
  • The columns repeat what the Text column already says
  • Horizontal scrolling to read one notification
  • No read state, no bell, no count
  • Sorted by time-of-day, ignoring the date

The proposal

  • Bell with an unread count in the top bar
  • 424px side sheet — the Events table stays visible
  • One row per notification, urgency as a colour bar
  • Details on demand, only fields that have values
  • Unread / All, per-user delete with undo
Use the bar at the bottom to switch Before / After and toggle the annotations.
