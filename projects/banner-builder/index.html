Internal admin · so managers can run temporary campaigns without a developer

MVP proto for discussion, not a spec. Everything here is one file, no backend.

Scope decided 2026-09-04: one banner at a time · not dismissible · targeting by plan · date + time + timezone · single optional button · plain text · every screen · no metrics, no pause, no approval step.

Campaign banners

System banners — trial expiry, failed payment, dunning — always win. A campaign banner shows only when no system banner is active for that user.

Open questions for the discussion

  1. How does the list identify a banner? Right now the body text is the identity — no separate internal name field. Fine at 5 banners, probably not at 50.
  2. Two overlapping campaigns: only one banner can show, and there is no priority field in the MVP, so the rule here is the later start wins. The builder warns when it detects an overlap. Alternative: an explicit priority number, which is one more field for managers to get wrong.
  3. Not dismissible + every screen + weeks-long campaign. A Christmas banner a user cannot close for 7 days is the thing most likely to generate support tickets. Worth revisiting even if the MVP ships without an X.
  4. Who can reach this page? No roles or audit trail in the proto. Anyone with the link can publish to all users.
  5. Copy review. Nothing checks the body text against vocabulary.md, so a manager can ship "payment platform" or "turn on".
  6. Yearly + Black Friday. Targeting by plan lets you exclude yearly subscribers from an annual-plan discount — worth confirming that is how marketing actually wants to slice it.
