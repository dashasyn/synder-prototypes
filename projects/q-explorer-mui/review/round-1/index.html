All six lenses ran, plus UX three times and Fidelity. Fidelity used the vanilla prototype as the specification, because the question this round was “were all features copied”. Nothing was skipped.

Scope. Round 1 covers the evaluations list and the app shell — login, top bar, filter bar, group accordions, table, row actions, header. New evaluation and the report views are declared not exercised and belong to round 2.

Known limitation. Most validators could not drive the live page this run and worked from the recorded state map and the shipped source. Every finding still names a reproducible interaction or quotes an exact string; the A11Y lens did drive a real browser.

Critical and High

CriticaldomainDOM-1

New evaluation → Filters card → the five scope selects (Transport Association, Transport Company (TU), Cantons, Lines, Stops)

Every one of the five scope filters offers the same two options, "SBB" and "BLS", so Cantons, Lines and Stops are populated with transport-company names instead of cantons, line numbers and stop names.

Impact. An authority user scoping an evaluation is shown a canton list containing no canton and a stop list containing no stop, so the scope they believe they set is not the scope the evaluation would run on, and the resulting punctuality figures would be attributed to the wrong dimension.

Fix. Populate each scope select from its own dimension — cantons from the Swiss canton list (Bern, Zürich, …), Lines from line numbers/Linienbündel, Stops from stop codes and names — and keep SBB/BLS only under Transport Company (TU).

Quote “SBB”
Source Domain rule (MISS-2026-09-16): a sample's shape is a factual claim, not decoration. The app's own glossary defines "TU — Transportunternehmen (transport company)" as a distinct entity from Kanton, Linie and Haltestelle; offering a TU as a canton or a stop is a category error, not placeholder text.

CriticaluxUX-1

Actions cell of Done rows in the 'Line Analysis DPM' and 'Trip Failures DPM' accordions

Finished evaluations in two of the six type groups expose only a Delete icon, so no control anywhere on the screen opens their report.

Impact. A user who locates the completed Line Analysis or Trip Failures evaluation they came for cannot read its result and the primary task dead-ends on a row that says Done.

Fix. Give every row whose status is Done an opener, or render a disabled opener with an inline reason stating why that result cannot be viewed.

Action In the 'Line Analysis DPM' group, went to the Actions cell of a row whose Status reads Done and looked for the preview (eye) control used on Done Punctuality rows; repeated in 'Trip Failures DPM'.
Observed Both cells contain a single Delete icon and nothing else — recorded action sets are done:line_analysis = delete and done:trip_failures = delete, versus visibility+delete on done:punctuality, done:data_quality and done:connection.

Higha11yA11Y-1fixed this round

Filter bar — Status and Period dropdowns (div[role=combobox])

Both filter dropdowns have an empty accessible name: the visible "Status" and "Period" labels are unassociated <label> elements with no for attribute and no id, and the comboboxes carry neither aria-label nor aria-labelledby.

Impact. A screen-reader user tabbing the filter bar hears "combobox, collapsed" twice with nothing to distinguish them, so they cannot tell which filter narrows by state and which narrows by date when hunting for an existing evaluation.

Fix. Give each MUI Select an id and its InputLabel a matching htmlFor (or add aria-label="Status" / aria-label="Period" to the Select) so the rendered label becomes the accessible name.

Action Tab from the Search box to the Status field, then Tab again to Period, and read the accessibility tree
Observed Playwright ariaSnapshot renders both as a bare "- combobox" with no name; in the DOM each div[role=combobox] has aria-label=null, aria-labelledby=null and id="", while its <label>Status</label> has for=null and id="", so nothing links the two.

Higha11yA11Y-2fixed this round

Row actions — the 11 "view", 3 "download" and 28 "delete" icon buttons in the Actions column

Every row action button is named only by its verb — aria-label="view", "download", "delete" — with no evaluation name, no aria-describedby and no row header to supply context, because the Name cell is a plain <td> rather than a th[scope=row].

Impact. A screen-reader user tabbing the list hears "view button" 11 times and "delete button" 28 times with nothing identifying which evaluation each belongs to, so opening the intended report — the primary task — becomes guesswork, and the same ambiguity sits on the destructive button.

Fix. Include the evaluation name in each button's accessible name (aria-label={`Open report for ${row.name}`} / `Delete ${row.name}`) and promote the Name cell to <th scope="row">.

Action Tab from the Punctuality DPM group header through the first six data rows (Tab x10)
Observed Focus stopped on buttons whose accessible names were, in order, delete, view, delete, view, delete, delete, view, delete, view, delete; counting the whole list gives 28 buttons named "delete", 11 named "view" and 3 named "download"; no button has aria-describedby or title, and the first cell of every row is <td> with scope=null.

Higha11yA11Y-3

Undo snackbar — the UNDO button, after confirming Delete in the confirmation dialog

Confirming the delete drops focus to <body>, and because the snackbar is portalled to the end of the document the UNDO button is tab stop 61 of 65 while the snackbar auto-dismisses after ~4.8 seconds.

Impact. A keyboard-only user cannot press roughly sixty Tabs inside a five-second window, so the undo that the dialog explicitly promises ("You can undo this for a few seconds afterwards") is unavailable to them and the deletion is effectively irreversible.

Fix. Move focus to the UNDO button (or to the snackbar) when it appears and hold the snackbar open while it or its contents have focus, restoring focus to the list afterwards.

Action Enter on a row's delete button, Tab to DELETE, Enter, then Tab repeatedly
Observed document.activeElement became <body>; the UNDO button measured as tabbable stop 61 of 65 and was only reached after 59 scripted Tab presses (181 ms at machine speed); the snackbar detached 4799 ms after it appeared. Its role="alert" is correct, so it is announced — it simply cannot be operated in time.

HighfidelityFID-1fixed this round

Evaluations list — the 4 rows with status Failed (e.g. "Pünktlichkeit – Aktuelles Jahr, BLS"), Actions cell and Name cell

The vanilla injects a "Run again" retry icon into every failed row, prints the failure reason under the evaluation name, and puts that reason on the status badge as a tooltip; the port renders failed rows with a Delete icon only and no reason anywhere, and although it copied FAIL_REASONS into data.js and fail_reason_source/timeout/nodata into i18n.js, nothing reads them.

Impact. A failed evaluation is a dead end again — the user is told it failed, never told why, and has no way to re-run it, which is exactly the defect the vanilla closed as M2.

Fix. Add a 'refresh' entry to ROW_ACTIONS wired to a retry handler, prepend it to the actions of every status==='failed' row, and render the FAIL_REASONS string already present in data.js both under the name cell and as the status chip's tooltip.

Quote “btn.className = 'action-icon action-retry';”
Source projects/q-explorer-prototype/index.html annotateFailedRows() (also act_retry: 'Run again', fail_reason_source: 'Data source was unreachable')

HighfidelityFID-2fixed this round

Evaluations list — Actions cell on every in_progress / running row (5 rows, e.g. "Rohdaten Export – SBB Vollexport Mai 2026")

The vanilla disables every action icon on a still-running evaluation and states the reason on hover; the port renders those icons fully enabled, so Delete opens the confirm dialog and removes a running evaluation.

Impact. The user can delete an evaluation that is still computing, an action the specification deliberately blocks (resolved as H15), and gets no explanation of why an action is unavailable because it never is.

MediumuxUX-5

Six type accordions with repeated table headers, and the non-sortable column headers

MediumuxUX-4

Evaluation name cell in the table, against the eye icon in the Actions column

The evaluation name — the thing the user is looking for and the obvious click target — is inert text, and the only entry point to a report is a small eye icon at the far right end of the row.

Impact.
