## Synder demo access SOLVED (12:25 UTC)

Got in. Working recipe, for next time:

1. **Cloudflare Access** — set the service token from `.synder-creds` as `extraHTTPHeaders`
   (`CF-Access-Client-Id` / `CF-Access-Client-Secret`). That alone is NOT enough: CF still
   demands an emailed OTP.
2. **OTP flow** — the code is bound to the browser session that requested it, so it must be
   request → relay → verify **without the browser context closing in between**. Request the
   code in one script that saves `storageState`, then verify in a second script that restores
   it. **Save storage state immediately after the verify click**, before attempting app login —
   losing the CF authorization cost two extra codes.
3. **App sign-in** — the email field is `input[type="text"]`, NOT `type="email"`. And
   `button:has-text("Sign in")` matches **"Sign in with Intuit"** first, which redirects to
   QuickBooks OAuth. Use an exact-text match on `Sign in`, or the submit inside the password form.
4. Landed at `/ui/dailySummaryControlPanel`. Mapping page is
   `/dailysummary/public/mapping/index.html` (sidebar: Mapping → Mappings list).
