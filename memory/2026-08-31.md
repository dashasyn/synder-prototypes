Answered from the Aug 19 capture set (`.synder-state/recon-create-2026-08-19/`) instead:

- **Non-contiguous ranges: impossible.** `07b-datepicker.png` — Date range is two inputs (from–to),
  one calendar, required, and it's the FIRST field. So gap-filling a partly-checked month needs
  multiple runs. Confirms "Check all of July" (re-run whole month) is the right CTA.
- **One integration per run — the product says so itself.** Get-started panel step 2:
  *"Choose the integration you want to reconcile. Reconciliation is done one integration at a time."*
  So multi-integration users MUST run once per integration. The per-account coverage problem I raised
  is structural, not hypothetical.
- **A record is created per run, keyed by account + integration + date range.** `40-after-submit.png`
  shows the Process log titled `Stripe mzkt.by (required for Synder)` / subtitle
  `mzkt.by (Stripe) / Jul 1 - 31, 2026` — created even on failure. Implies re-running produces a
  SECOND record rather than updating the first, but that needs a live successful re-run to confirm.
- Day-level coverage per account IS derivable from the list (each record carries its range); whether
  it's cheap at dashboard load stays an engineering question.
