### Two mistakes worth keeping

1. **A balanced global div count proved nothing.** After the first pass, opens−closes over the
   view segment came out to exactly 1 (the view div) — looked correct. It wasn't: the TU row
   was missing its `</div>` and a later row had a spare, so the two cancelled. In the browser,
   rows 3–6 nested inside the TU row and spilled outside the card. **Assert structure, not
   totals**: `filter-section > .filter-row` direct-child count, `.filter-row .filter-row`
   nested count = 0, one `.filter-control` per row.
2. **`showView('rohdaten')` is not the entry point** — `showRohdaten()` is, and it seeds the
   date range, the TU/lines/stops lists and the note. Driving the view directly gave an empty
   Zeitraum field and an empty note box that I nearly reported as bugs. Same class as the
   "recon choices are coverage claims" lesson: **enter through the route a user takes.**
   Also: `rdRun()` adds the export inside a `setTimeout`; a 700ms wait read as "Run is dead",
   a 3000ms wait showed 3→4. Don't call something broken on a short wait.

Also caught and fixed before shipping: constraining `.rd-config` to 800px clipped the
"Erstellte Exporte" params strip. The produced-exports list is a *result* list — moved back
outside the wrapper to full width, like the evaluations list.

## Filters reworked: clear-X instead of an "Alle" option — `c8d306e`

Ignat on the sample: "I like the visuals. Inputs look very MUI. But I want filters work
different. I don't like 'All' as a selectable option. I prefer a cross to clear the filter."

That is exactly MUI `<Autocomplete>` semantics, so it's a fidelity *gain*, not a deviation:
- **No "Alle" entry in any list.** An empty field is an unfiltered field.
- **Label rests centred while unset**, lifts only once a value exists — so "unfiltered" is
  legible without a word for it.
- **Clear ✕ beside the popup caret**, `visibility:hidden` until the field is hovered or
  focused *and* holds a value (MUI's real default).
- Native `<select>`s became real comboboxes: elevation-8 Paper listbox, 36px options,
  selected row at primary 8%.

### The trap this walked straight back into
Critical #1 of the 2026-08-27 review was a clear-✕ mounted dead centre of the filter, so the
natural "click it again to see my options" gesture silently wiped the value. Adding a clear-✕
is the same feature that caused it. Both indicators are therefore pinned to the right edge,
there's a source comment saying not to re-centre them, and there is now a **standing regression
test**: click the exact horizontal+vertical centre of a filled filter, assert the value
survives and the listbox opened. Reuse this whenever a clear affordance is added anywhere.

Filters are wired rather than decorative — search + status + period + type intersect, group
counts and the total recount, empty groups hide, no-results state explains the reset.

Verified in Chromium: 0 "Alle" options · ✕ hidden empty / visible on hover+value ·
centre-click keeps value and opens list · ✕ restores 5 rows · two filters → 0 rows + empty
state · no console errors.

**Offered but not decided:** ✕ could be always-visible instead of MUI's hover/focus reveal —
one line. Full restyle of the other 15 views still not started, still awaiting go.
