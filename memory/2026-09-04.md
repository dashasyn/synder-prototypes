
## Everrunning music V2 — schedules per station (Ignat, 13:57)

Asked questions first (10 of them, each with a default) — he answered all 10, then I built. That's
the loop from `AGENTS.md` working as intended: one round of questions, one clean build.

**His screenshot turned out to be our own Schedule dialog** — the weekly Mon–Sun grid from the
transfer announcements in this same prototype. So V2 reuses that component instead of inventing
one; the only change is that it lives inline in the entry card (music and radio visible together
while checking overlaps) and that days start empty.

**Decisions he made:** one row per station with Musik/Radio columns and day-of-week detail · row
click opens a full-screen detail, no expander · validity per entry (Oct 1–31 weekends for
Oktoberfest) · music and radio may share a day but must never overlap ("do not allow for now,
maybe later priority options") · single track loops, with an interval option · `Apply to` **copies**
· one schedule per station, so applying **overwrites** the target · start empty · drop the
per-station override · default for the picker path.

**Two calls of mine, both flagged to him:**
- Overlap is checked on a Mon 00:00 → Sun 24:00 minute timeline, so `end < start` means *across
  midnight* — the existing transfer schedules already use 22:00–01:00, so refusing it would have
  been wrong.
- The per-station override stays in **V1** (the version he wants to keep developing) and is simply
  absent from V2. His "delete it" was answered about the new model.

**Applied his own earlier feedback unprompted:** the apply dialog is tall enough to scroll, so
`.modal-actions` is now pinned to the bottom of every modal box — and the overwrite warning rides
in that same bar, because a warning that scrolls away from its button is the exact defect the
message-generator round found.

62 Chromium checks in `verify-music.js`. Test bugs of mine along the way: wrong element ids
(`ms-week-N` is the tbody, `ms-N-D-S-s` the input), row-count arithmetic that forgot `apply` also
saves the source station, and a strict-mode violation because a station on three lines appears in
three line groups — which turned into a useful check that the three checkboxes stay in sync.

Also: seeded schedules listed only the days they used while drafts always carry seven, so
`stationSchedules` is now normalised at boot — stored and edited schedules have one shape.
