## Banner builder — MVP proto (Ignat, 15:38)

New project. Managers need to run temporary campaign banners (trial, subscribe, Black Friday,
Christmas) without a developer. He asked for questions first, I posted 11 with defaults, he answered
all 11 in one numbered list — the ask-before-building loop working exactly as intended.

**Scope he settled:** low priority vs system banners (already built, so out of scope) · one banner
at a time · targeting by plan (trial / monthly / yearly / accountants) · **not dismissible** ·
date + time + timezone · a page listing scheduled banners · plain text · single optional button ·
every screen at the top · no metrics, no pause, no approval step. Purpose: "a simple proto to start
discussion. To understand is it a good idea or not."

**Built:** `projects/banner-builder/index.html` — list page + full-screen builder overlay, one file,
UI kit only, no raw hex. Colour is 4 fixed token presets (blue = `--color-banner-info`, the
production banner blue), not a picker.

**The part worth discussing** — his answers have a gap: one banner at a time, but no priority field.
So overlapping campaigns need a tie-break. I implemented *later start wins* and made the builder and
the list **warn on overlap**, naming the other banner, the shared audience and which one wins. Zero
new controls. Six open questions listed on the page, incl. not-dismissible + every-screen + 7-day
Christmas banner as the most likely support-ticket generator.

**Two real bugs my own preview caught:**
- `getBoundingClientRect().height` returns the **transformed** height, so the wrap warning read
  1 line inside a `scale(.375)` preview. `offsetHeight` is untransformed layout — use that when
  measuring inside a scaled frame.
- A submit-time field error outlived the value that caused it: red "140 characters" under a
  39-character field. Submit-time validation still needs per-field clearing on input.

Also: the kit's `.material-icons` class has **no font loaded** in any prototype, so icon ligatures
render as the literal words "error" / "warning". Use text or unicode. Asserted against now.
