## Morning idea (2026-08-14) — DIS-259 "See details" with no detail to show

Grounded in the oldest unverified item on the Balance Reconciliation list: the Error-status
"See details" wiring, flagged unverified at review time and never checked since.

The unspecced edge case: an Error row whose error carries **no detail payload**. The
normalization failures in the 08-10 LogRocket data (Stripe/Amazon files — unrecognized date
formats, missing columns) are exactly this class, and often have no structured reason. Today
the link renders unconditionally, so it either opens an empty panel or does nothing — a dead
click. Same failure class as the read-only-promise card and the "Are you sure?" dialog from
08-10: **UI offering something it can't deliver.**

Fix: make the link conditional. With a detail payload, keep "See details". Without one, drop
the link and put the raw reason inline in the row ("Couldn't read the date column" /
"Synder couldn't match this to a payout") — even the unpolished backend string. A
wrong-sounding reason beats a link to nothing. ~10 min of copy plus one eng question: *does
every Error status have a detail record, or only some?* That answer also closes the wiring
item that's been open since the review.
