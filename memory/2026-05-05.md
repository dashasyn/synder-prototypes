### Domain Understanding: Transit Data Manager
Ignat is designing a **Transit Information Management System** for railroad/bus operators. Key concepts learned:

**Core Data Model:**
- **Schedule** = validity period (e.g., "Summer schedule" Jun 1 - Aug 31)
  - Contains multiple Routes
- **Route** = a specific train line with ordered station sequence
  - Same route can vary between schedules (e.g., Summer route stops at "Old Church", Winter doesn't)
  - Routes vary by: season, weekend/weekday, direction (A→B vs B→A different station order)
- **Station** = stop on a route, has position/order within route context

**Message System:**
- Each station generates messages for devices on the train
- **Device types** (configured per transit company):
  - Front screen: destination city
  - Side screen: route/destination
  - Inside screen: next station
  - Audio announcements
- Company A might only have front screens; Company B has all 4 types
- Device list is predefined per company by admins

**Message Types:**
- Front/side: Destination station (static during journey)
- Inside screen after departure: "Next station: XXX"
- During stop: Current station name
- Additional: "Passengers to airport please change here"
- Trigger types: door close → "Next station", GPS 100m before → approach messages

**Rules System (key insight):**
- Currently managers manually add "Next station: Central Square" to every route for every train (50 trains in NYC = 50 manual entries of same message)
- Goal: create rules that auto-generate messages
- Default rule: "Next station: {NEXT_STATION}" applies to ALL stations
- Station override: can customize for specific station
- Route/schedule override: can customize for specific train
- Priority: Station-specific > Schedule-specific > Default rule
- When manager adds station to route, system auto-generates messages based on rules

**Key pain point:** Manual, repetitive work creating same messages across many routes/trains

**References:**
- Replit prototype: https://station-configuration--tututrurututu.replit.app
  - Has: Map, Timetable, Journeys, Routes, Admin navigation
  - Routes has: Station configuration, Routes configuration, Sound library
  - Shows route list (RT001, Line 101, Berlin Hbf → Munich Hbf, validity period)
- Figma prototype: https://alpha-enjoy-65633009.figma.site/
  - Figma lacks business logic — purely visual
- Assessment: Figma prototype is visually good but missing the rules/generation logic
