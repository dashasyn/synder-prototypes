## ETC ELA generator — v4 published, v5 built (Ignat, 20:02)

**First, a correction I had to make to myself.** "Let's continue with AI messages for metro" →
loaded context and found the whole validator round + sticky footer sitting **uncommitted** in the
working tree. On 09-01 I told Ignat they were "applied". They were applied *locally*; the live URL
served v3 for two days. Checked it properly this time: `curl` of the Pages URL md5-matched
`git show HEAD:…`. Rule: publish, then report — "applied" without a push is not applied.

**v5, six changes from Ignat, all inside the existing structure:**
1. `Quelle` has four points now — Standard · Bibliothek · Aufnahme · **Empathisch**. Empathetic is
   our AI part: the only source with a prompt, the only one where GENERATE ELA is enabled.
2. Tone-of-voice selector gone. Variants are now three per notice type, not three per tone per type.
3. `Zusätzliche Angaben` is a separate field again.
4. Prompt is **read-only** — assembled from line/stations/reason, so no invented bus route.
5. `STANDARD`/`DEFAULT` reset button gone (nothing left to reset).
6. All three ELA buttons in one row: ELA GENERIEREN · AUDIO ERZEUGEN · ANHÖREN.

**Two calls I made while building, both flagged to him:**
- **Standard = the predefined system message**, loaded on open. An *untouched* system text follows
  the Erst-/Hauptmeldung switch instead of going `Ereignis geändert`; anything a human generated,
  picked or edited still goes stale. Otherwise "Standard" would be a mode that shows nothing.
- **Playback simulated, `speechSynthesis` removed** — his 09-01 note, "we don't need actual audio
  generation. It is just a prototype." Suite went from 10+ min to ~90 s.
- Audio key no longer includes `Quelle`: switching source without touching a word must not stale a
  current file.
